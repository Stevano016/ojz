# OZJ Reporting System — Implementation Plan

A full-stack reporting/ticketing system for the OZJ AI Signal Intelligence Youth Care workflow. Built with **Laravel** (API backend) and **React.js** (frontend SPA). The system tracks tickets generated by n8n webhooks and manual input, shows dashboard charts, and syncs with Google Sheets.

## Data Model (from Google Sheets)

The spreadsheet has **34 columns** per ticket row:

| Key Fields | Description |
|---|---|
| `ticket_id` | e.g. OZJ-20260310-4535 |
| `judul_sinyal` | Signal title |
| `deskripsi_sinyal` | Signal description |
| `level_sinyal` | Mikro / Meso / Makro |
| `urgensi_sinyal` | Rendah / Sedang / Tinggi |
| `kategori_sinyal` | Category (Verwaarlozing, Akses Layanan, etc.) |
| `skor_urgensi_hukum` | 0–100 legal urgency score |
| `status_ticket` | Open / In Progress / Resolved / Closed |
| `status_eskalasi` | Normal / Sedang / Tinggi / KRITIS |
| `dasar_hukum` | Legal basis (Jeugdwet, UNCRC, etc.) |
| `waktu_catat` | Timestamp |
| `jenis_sumber` | whatsapp / input-manual |

## Proposed Changes

### Backend — Laravel API

#### [NEW] `d:\Coding\hackaton\ozj-backend\` (Laravel project)

Created via `composer create-project laravel/laravel ozj-backend`.

#### Database Migrations

1. **`users`** — Internal login (id, name, email, password, role)
2. **`tickets`** — All 34+ columns from spreadsheet mapped to DB columns:
   - `ticket_id` (string, unique), `ringkasan_sinyal`, `judul_sinyal`, `deskripsi_sinyal`, `level_sinyal`, `urgensi_sinyal`, `kategori_sinyal`, `nama_program`, `nama_pelapor`, `nama_lokasi`, `risiko_teridentifikasi`, `rekomendasi_ai`, `jenis_sumber`, `waktu_catat`, `wa_chat_id`, `status_ticket`, `status_eskalasi`, `waktu_eskalasi`, `rekomendasi_keputusan`, `skor_urgensi_hukum`, `dasar_hukum`, `bahasa_output`, `nama_pengirim`, `nomor_pengirim`, `level_laporan`, `urgensi_awal`, `timestamp_laporan_ai`, `skor_urgensi_tertinggi`, `sinyal_index`, `sinyal_total`, `rr_tenggat_waktu`, `rr_tindakan_utama`, `rr_pihak_yang_dihubungi`, `rr_langkah_dokumentasi`
3. **`ticket_actions`** — Progress/action log per ticket:
   - `id`, `ticket_id` (FK), `user_id` (FK), `action_type`, `description`, `created_at`

#### Models
- `User` — with Sanctum for API auth
- `Ticket` — hasMany TicketAction
- `TicketAction` — belongsTo Ticket, belongsTo User

#### API Routes (`routes/api.php`)

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/login` | Auth login, returns token |
| POST | `/api/logout` | Revoke token |
| GET | `/api/user` | Current user |
| GET | `/api/tickets` | List tickets (filterable, paginated) |
| POST | `/api/tickets` | Create ticket manually |
| GET | `/api/tickets/{id}` | Ticket detail |
| PUT | `/api/tickets/{id}` | Update ticket (status, progress) |
| POST | `/api/tickets/{id}/actions` | Add action/progress entry |
| GET | `/api/dashboard/stats` | Aggregate stats for charts |
| POST | `/api/webhook/n8n` | Receive ticket from n8n (unauthenticated) |

#### Seeders
- `UserSeeder` — creates default admin user (`admin@ozj.nl` / `password`)
- `TicketSeeder` — imports sample data from spreadsheet

### Frontend — React.js (Vite)

#### [NEW] `d:\Coding\hackaton\ozj-frontend\` (Vite React project)

#### Pages & Components

1. **Login Page** — Email + password form, stores JWT token
2. **Dashboard** — Charts using `recharts`:
   - Tickets by urgency level (bar chart)
   - Tickets by status (pie chart)
   - Score distribution (area chart)
   - Tickets by category (horizontal bar)
   - Recent tickets table
3. **Ticket List** — Searchable, filterable, sortable table with status badges
4. **Ticket Detail** — Full ticket info + action history + add progress form
5. **Create Ticket** — Manual ticket input form with all fields
6. **Layout** — Sidebar navigation, user menu, responsive design

#### Design
- Dark mode with gradient accents
- Glassmorphism cards
- Smooth transitions/animations
- Google Fonts (Inter)
- Color-coded urgency badges (red=KRITIS, orange=Tinggi, yellow=Sedang, green=Normal)
